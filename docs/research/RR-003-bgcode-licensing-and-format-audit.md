# RR-003 — Binary G-code (`.bgcode`) licensing & format audit

**Status:** Complete
**Author(s):** Nathaniel Chestnut
**Date:** 2026-07-27
**Owning Epic:** E-bgcode (#188) · **Informs:** DD-011 (Binary G-code Decode Adapter) — the epic's DD gate

## 1. Question & the decision it informs

Epic #188 wants `.bgcode` files to flow through the **existing** pipeline (parser → dialects → IR →
renderer → progress), since `.bgcode` is a *container/encoding* of ordinary G-code, not a new toolpath
language. Before DD-011 can specify the decode adapter, this RR must answer:

1. **Is decoding legally clean for an MIT project?** The reference implementation (`libbgcode`) and the
   MeatPack encoder are **copyleft**. Which parts may we port, and which must be clean-roomed?
2. **What exactly is the format?** Block structure, block/compression/encoding IDs, checksum — pinned to
   a spec version, precisely enough for DD-011 to specify a decoder.
3. **What can we reuse vs. build new**, and where are the correctness/security risks?

Decision it informs: *the scope, package shape, per-codec sourcing strategy, and security gates of
DD-011.*

## 5. Measurements & observable results — the format (spec v1, little-endian throughout)

### 5.1 File header (10 bytes)
| Field | Bytes | Notes |
|---|---|---|
| Magic | 4 (u32) | ASCII `"GCDE"` |
| Version | 4 (u32) | **1** (pin; reject others) |
| Checksum type | 2 (u16) | 0 = None, **1 = CRC32** |

### 5.2 Block layout
`block header → parameters → data → optional checksum`

**Block header:** `type` u16, `compression` u16, `uncompressedSize` u32, and — **only when compression ≠
0** — `compressedSize` u32 (⇒ 8 bytes uncompressed, 12 bytes compressed).

| Block type ID | Meaning | Compression type ID | Algorithm |
|---|---|---|---|
| 0 | File Metadata | 0 | None |
| 1 | GCode | 1 | DEFLATE |
| 2 | Slicer Metadata | 2 | heatshrink (window 11, lookahead 4) |
| 3 | Printer Metadata | 3 | heatshrink (window 12, lookahead 4) |
| 4 | Print Metadata | | |
| 5 | Thumbnail | | |

**Block parameters:**
- Metadata blocks (0/2/3/4): `encoding` u16 — 0 = INI.
- Thumbnail (5): `format` u16 (0 = PNG, 1 = JPG, 2 = QOI), `width` u16, `height` u16.
- GCode (1): `encoding` u16 — 0 = None, 1 = MeatPack, 2 = MeatPack (comments preserved).

**Checksum:** when the header's checksum type ≠ 0, each block is followed by a **CRC32 (4 bytes)** over the
block's header + parameters + data.

### 5.3 Decode pipeline implied by the spec
For each GCode block: read header → (if compressed) decompress `compressedSize`→`uncompressedSize` bytes
via DEFLATE **or** heatshrink → (if encoded) MeatPack-decode → append the resulting ASCII G-code. Concatenate
all GCode blocks in file order → hand the plain G-code to the **existing** parser/dialect stack unchanged.
Metadata/thumbnail blocks optionally surface `MachineGeometry`/thumbnails via the existing sink.

## 6. License / provenance concerns (the gating finding)

- **AGPL contamination is the headline risk.** `libbgcode` (reference decoder) and OctoPrint-MeatPack are
  **AGPL-3.0**. We must **never** copy, translate, vendor, or WASM-bundle their source into our MIT
  packages — that would relicense our stack. Both are *reference/verification* material only.
- **heatshrink is ISC** — permissive and MIT-compatible. We **may port** the LZSS decoder to TypeScript
  **provided we preserve the ISC copyright/permission notice** in the ported file. This is the recommended
  path: LZSS bit-streams are error-prone, and a license-clean port is lower-risk than clean-rooming.
- **MeatPack must be clean-roomed** from the *algorithm* (two 4-bit nibbles/byte over the ~15 most common
  G-code characters; nibble `0b1111` escapes a full ASCII byte; `0xFF 0xFF <cmd>` toggles packing). The
  **exact 15-entry nibble table is code, not concept** — DD-011 must source it cleanly (derive+validate
  against self-generated plain-vs-`.bgcode` pairs, or transcribe from the *spec text*, never from AGPL C).
- **DEFLATE / CRC32 carry no new provenance** — platform `DecompressionStream` and our own MIT `crc32`.
- The **format spec itself is an interface/idea**, implementable from the published description under
  standard clean-room practice; auditing it here does not taint our implementation.

## 7. Limitations & unknowns (for DD-011 to resolve empirically)

- **DEFLATE flavor** — zlib-wrapped (`DecompressionStream('deflate')`) vs raw (`'deflate-raw'`) is not
  stated; resolve against a real file (the killer test makes this self-correcting).
- **MeatPack table fidelity** — the exact character↔nibble map and the whitespace/`E`-substitution and
  signal-byte handling must be reconstructed and validated, not lifted.
- **heatshrink parameters** — window 11 vs 12 / lookahead 4 are selected per block by the compression ID;
  the decoder must be parameterized and the bit-ordering validated against vectors.
- **`DecompressionStream` in workers** — available in browsers and Node ≥ 18, but the batteries/slim worker
  registration and any fallback must be confirmed (DD-003 territory).
- This RR establishes *legal + structural feasibility*, not decode throughput — benchmarked in DD-011 §8.

## 8. Recommendation & rejected alternatives

**Recommendation — proceed to DD-011** with a new **`@chestnutlabs/gcode-bgcode`** package that plugs into
the existing container-adapter contract (`{ id, sniff, open }`) beside `.gcode.3mf`, decoding to plain
G-code so the whole downstream stack is reused unchanged. Per-codec sourcing:

| Codec | Strategy | Basis |
|---|---|---|
| DEFLATE | reuse `DecompressionStream` | already shipped for `.gcode.3mf` |
| CRC32 | reuse our `crc32`/`crc32Final` | MIT, ours |
| **heatshrink** | **port from the ISC source, keep the ISC notice** | ISC permits; safest for correctness |
| **MeatPack** | **clean-room the algorithm; source the table cleanly** | AGPL forbids copying |
| block walker / sniff / open | new, clean-room from the spec (§5) | spec is an interface |

DD-011 must carry: the **killer golden-equivalence test** (decoded-`.bgcode` IR **==** plain-`.gcode` IR),
published/derived **codec vectors**, an **adversarial corpus**, a **bounded-output guard** on every
decompressor (decompression-bomb defense), **version/compression/encoding pinning with honest rejection**
of unknowns, and a **§7.3-style security review sign-off** (as DD-005 required). No `.bgcode` **encoding**
(decode-only), no multi-plate.

**Rejected alternatives:**
- **Vendor/link `libbgcode` (or compile it to WASM).** Rejected — AGPL-3.0 would relicense our MIT stack.
  Its only role is cross-checking our output.
- **Copy/translate OctoPrint-MeatPack.** Rejected — AGPL. Clean-room the algorithm instead.
- **Clean-room heatshrink too.** Rejected as unnecessary risk — ISC already permits a license-clean port,
  and hand-rolling LZSS invites subtle bit-stream bugs; port + attribute.
- **A new top-level toolpath model for `.bgcode`.** Rejected — it decodes to ordinary G-code; it is a
  container, and belongs beside the existing container adapters (E4 machinery).
